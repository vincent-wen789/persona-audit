# 引擎模式

用于持续生成用户可见文本或卡片的产品：报告、推送、每日简报、readout。默认仍是 **report-only**；样本生成和审计不授权修改、commit、部署或发布。

## 0. 确认目标

确认本次要审的版本、输出层和用户触达面。用户没说时只问这一项，因为它决定样本分支和第 4 个读者角度。

## 1. 生成 6–8 份真实样本

把样本存到 `/tmp/<product>-audit/`，覆盖三轴：渲染分支 × 边缘数据形态 × 用户触达面。

- 有演示或全亮开关：运行真实演示命令，并说明哪些内容是强制点亮、线上不会同屏。
- 已上线但无开关：采集真实输出前先脱敏，记录来源，不把生产 secrets 写进样本。
- 未上线且无开关：构造测试数据或写临时 dump 脚本，不能手改输出伪造样本。

最小覆盖：普通态、极值、缺数据、对比/汇总视图、直达用户的邮件或推送，再按关键分支补足。

视觉产出用渲染截图；同名 OCR 文本只作小字备查。

## 2. 填 4 个读者角度

从 [`../templates.md`](../templates.md) 取身份块：主用户镜像、纯新手、挑剔老手、新功能目标用户。若目标用户与主用户相同，把第 4 个换成首次接触者或相邻读者。

同一目标的复审沿用上次存档的身份块；换目标文档就重建，不跨文档复用。

## 3. 冷读

按 [`../SKILL.md`](../SKILL.md) 的证据模式运行：

- 隔离上下文才可以统计 N/4。
- 单一上下文只能称“多视角收敛”。
- 每个 reader 只读中性样本 bundle，不读代码、产品文档、设计宪法或其他 reader 的回答。
- reader 没有样本目录外读取、网络、写入、发布或 secrets 权限。
- 演示全亮样本必须写明真实环境只出现多少条，避免把演示同屏报成矛盾。

画像 prompt = 身份块 + 冷读纪律 + 报告结构 + “重点报缺失信息” + “引用原文和情绪反应”。视觉样本使用 `templates.md` 的视觉骨架。

## 4. 汇总并存档

汇总前，主流程可以读取产品宪法或设计铁律；冷读 reader 不可以。输出顺序：

1. **运行清单**：日期和时区、目标版本、runtime/model、证据模式、样本来源、4 个身份块、完整 prompt。
2. **共识矩阵**：合并同一根因；隔离模式可列 N/4，单次模拟只列涉及的角度名称。
3. **资产确认**：单独列“别砍清单”。
4. **ABCD 分层**：
   - A 卫生：错别字、确定的数字错位等无争议硬伤。
   - B 真 gap：方向无争议但需要产品工作。
   - C 张力点：与既有定位或设计哲学冲突，交给 owner 决定。
   - D 边界外：数据拿不稳、定位外或不是这把尺能判断。
5. **原始证据**：保留每个隔离 reader 的原文；单次模拟保留完整一次输出。不要把整理后的矩阵冒充原始报告。

存到产品 repo 的 `reviews/<product>-persona-audit-<date>.md`。同日复审加版本后缀，不覆盖旧档。产品 repo 可能公开时，存档前再次检查脱敏和私有路径。

票数和优先级是两列：多数角度想要的东西仍可能是 C/D；一个角度抓到确定数字错误仍然是 A。没有设计宪法时，只把确定硬伤放 A，其余进入 B/C 候选。

## 5. 可选修复阶段

只有用户明确要求“应用修复”后才开始：

1. 复述要改的 A/B/C 项和允许修改的文件范围。
2. C 项先取得 owner 决定。
3. 修改后跑产品测试和真实输出验证。
4. 让原先撞上问题的角度回读改动句和前后文；核心定位、安装或价格变动则全 4 角度重读。
5. 返回 diff 和验证结果。

**不要把部署/同步当成修复阶段的默认尾步。** 发布、部署、外部消息和生产写入都需要单独授权。

## 私有绑定

把产品特定值填进 `LOCAL.md`；该文件已 gitignore：

| 钩子 | 用途 | 缺省 |
|---|---|---|
| 设计宪法 | 判断 C 层 | 缺失时只把确定硬伤放 A |
| 存档位置 | 审计记录目录 | 产品 repo 根目录 |
| 样本生成 | 可实际运行的命令或采集方式 | 使用上面的三档降级 |
| 修改后验证 | 测试命令、禁词检查、真实输出命令 | 至少运行产品现有测试 |
| 发布流程 | 仅在用户单独授权发布后参考 | 不发布 |

## 失败恢复

| 失败 | 处理 |
|---|---|
| 隔离 reader 缺员或超时 | 重试一次；仍失败就按实际镜头数输出并注明缺员 |
| 无法隔离上下文 | 降级为单次多视角模拟，移除 N/4 票数 |
| 报告无引用或结构走样 | 补发一次；仍空泛则作废该份 |
| 样本生成失败 | 修命令后重试；不能手改输出，无法取得真实样本就停下说明 |
| 原始输出或模型信息没保存 | 明标“不可复核”，不要称完整可复现运行 |

## 常见错误

- 把收敛票数直接当优先级。
- 为了“给方案”而编造试用、退款、隐私或功能事实。
- 把 raw HTML、代码注释或作者笔记当成用户可见刺激物。
- 把 prompt-injection 纪律宣传成安全保证。
- 审计请求后直接编辑、commit 或部署。
- 只列问题，漏掉资产确认和未知项。
