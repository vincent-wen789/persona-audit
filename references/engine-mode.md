# 引擎模式

用于跨多个渲染分支审计持续生成的报告、通知或结果卡。沿用 SKILL.md 的读者、目的、表达代价和事实边界，不因为是引擎就增加恐慌人设或问题配额。审单份输出用轻量模式。

## 覆盖决定样本量

先从请求确认版本、输出层和触达面；已有信息直接用，缺失且影响覆盖时才问。先取 2–3 个不同分支的真实输出；仅在尚有重要分支未覆盖时增加，报告覆盖和遗漏，不用固定凑 6–8 份。

- 用真实输出或真实引擎加测试数据；不能手改输出伪造测试结果。
- 按实际存在的正常、缺数据、极值/异常和触达面选样，不要求产品没有的分支。
- 演示全亮样本须说明哪些内容线上不会同屏，避免报假矛盾。
- 先脱敏；视觉输出用渲染截图，OCR 只备查。生成脚本仅在现有任务授权范围内操作，不使用会触发生产写入的命令。

## 冷读与合并

按 [templates.md](../templates.md) 选受众内的阅读差异，默认两视角、同一次调用覆盖少量代表样本。明确要求四画像或隔离时按请求运行，不把“能调用 agent”当成扩展理由。隔离 reader 不读代码、作者笔记或其他回答；工具权限需实际限制，不能假定 prompt 已实现隔离。

同一根因跨样本只报一次，附出现位置；新增分支只查增量。主线程可用产品既有定位判断建议是否相关，但不能拿文档替读者补足不可见信息。

输出覆盖说明、值得处理的发现、应保留的表达、影响结论的未知项。需要产品任务分层时才加 ABCD：
- A：确定的文案或显示错误。
- B：妨碍既定目标、需要产品工作的 gap。
- C：涉及用户尚未授权改变的定位或表达取舍。
- D：目标外需求或当前材料无法判断。

这些是处置类型，不是严重度。没有产品宪法不阻止冷读，也不自动制造 C 项。

## 记录与复审

默认在对话返回简报。用户要求存档或项目已有记录约定时，保存到指定位置或产品 repo 的 reviews/，不覆盖旧版。最小记录：目标/版本、样本来源、覆盖、所选身份、证据模式、实际已知的 runtime/model、prompt、原始输出。未知元数据标未知；原文只保存一次，汇总用链接，不复制进多份附录。公开位置先脱敏。

用户已授权修改时继续完成局部修复和相应验证，不重复问已有授权；未决定的方向取舍集中提出。回读改动及相关分支，同时检查理解和表达效果；没有新问题就结束，不自动重跑整套审计。审计或修改授权不包含发布、部署和生产写入。

样本无法取得则说明限制，不伪造；reader 缺员或输出空泛时仅在影响结论时补一次，仍失败就按实际覆盖报告，不为凑人数循环。
